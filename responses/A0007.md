## 1. Outcome and correction

**The library's job is to identify useful technology and rank alternatives by future task.** This report returns to that job. It contains **40 primary catalog entries across eight families, 24 deeper evidence cards, same-role comparisons and a capability lookup**. Versions, quantizations, ports and model backends are not counted as independent new discoveries.

The main findings are:

- **Local CPU inference:** standalone llama.cpp, KoboldCpp and Ollama remain differentiated candidates; Lemonade now deserves attention for an embeddable server and several model types; ONNX Runtime GenAI/Windows ML is a different ONNX deployment route. No evidence proves one fastest on this Lenovo. FastFlowLM's newer Ryzen AI NPU requirement excludes this 3500U from that backend, while preserving the technology for future hardware.
- **Small models:** Qwen3.5-0.8B, Granite4.0-H-1B, Gemma3-1B and Qwen3-1.7B present different size, language, template and licensing trade-offs. **There is no proven best Persian model here.** Granite and SmolLM3 multilingual labels are not Persian qualification. A dedicated multilingual embedding model or OCR/ASR tool may solve a narrower task better than a chat model.
- **Native useful components:** ripgrep is a strong provisional library addition for searching text without a server or model. Process Governor, Windows Job Objects and llama-swap solve different resource problems; none makes an oversized model fit physical RAM. Lemonade's default one-model limit is per model type, with separate routing-helper residency in current documentation.
- **Document work:** compare MarkItDown for ordinary file-to-text conversion, Docling for structured/layout-heavy documents, Tesseract for Persian OCR, and lexical search before additional embedding infrastructure. New Docling packaging is modular; “MIT” does not license every downloaded model. MarkItDown's optional LLM-vision OCR can silently be skipped without its client.
- **Free services require current qualification:** Brave now documents monthly $5 credits with a card and prepaid/auto-reload distinctions. Tavily's monthly credits are real but its terms explicitly restrict Iran. HF documentation says new CPU Basic compute Spaces require a paid subscription despite zero hourly CPU price. Cloudflare publishes actual Free allowances, but this report has not established this user's service/account/region entitlement.

**Correction to A0006:** equivalent Oct17/19 Windows observations already existed. Another D0 is not a prerequisite to discovery. This report contains no diagnostic script, installation recipe, fixture, implementation schema, deployment plan or pilot design. A0001–A0006 remain historical research; their execution priorities are superseded by the newest library-first direction.

Installed products receive **zero technical merit bonus**; new products receive **zero novelty bonus** and no installation penalty. A ready product can eliminate custom language/framework work when it supplies the needed capability. These are research shortlists, not instructions to install or activate anything.

These are **historical measurements, not model benchmarks**.

Fit labels are ANALYSIS, not pass results:

- **L — probable lightweight:** small/native utility or small quantized model with bounded task/context; no promised whole-stack peak.
- **T — conditional/tight:** model/backend/index/browser combination can exceed available memory or needs substantial dependencies.
- **N — not practical as resident S0 / incompatible route:** NPU-only engine, unsupported accelerator, large model/context or heavyweight media pipeline.
- **Remote — server computation elsewhere:** laptop cannot disqualify the server; browser/client and privacy still matter.

File size is not RAM. Whole cost includes host/UI/helpers, engine, resident weights, KV/recurrent state, buffers, document/index workload and browser. UMA shared memory is not extra RAM; pagefile is not an8→24GiB physical upgrade. No RAM cleaner, fake VRAM fix, BIOS/pagefile/driver modification or new diagnostic is recommended here.

### 4.1 A1 — llama.cpp: direct GGUF inference, not a complete assistant

**Identity/date:** EE, R004 lineage; [v0.7.0 release](https://github.com/ggml-org/llama.cpp/releases/tag/v0.7.0),2026-10-15; [tagged server documentation](https://github.com/ggml-org/llama.cpp/blob/v0.7.0/tools/server/README.md), blob4e4472ec24bd0822be30e327aecd549cc15a2bc8. MIT engine; weights separate.

**Use/placement:** a future assistant requests local text, embeddings or schema-constrained output from a native Windows CPU server.
